## 0. 冻结决策速览

| 域 | 决策 |
|---|---|
| 总形态 | **单大脑 + N 执行面**，星型拓扑；池 = 可挂载任意 harness 的工具，不做独立 Harness 应用 |

## 2. 身份、凭证与入池

### 2.1 密钥体系（双层）

- **hub root keypair**（Ed25519）：hub 身份，签发节点凭证与 `/node` 端点证书；**随 hub 状态迁移**（P5）。
- **节点凭证**：root 签名的证书，含 `node_id`、`epoch`、有效期；节点 pin root 公钥 → 迁移后自动信任新 hub、拒绝旧 epoch。
- 存储：节点凭证与 root 私钥均走 credstore（**DPAPI/Keychain**；hub 按 §6 跑在用户会话档，自启兼容）；`hub.db` 明文 + OS 目录权限（文档建议：开启 BitLocker/设备加密；`.mdp` 目录禁止云同步）。
- `node_id` = 公钥哈希 16 hex（主键）；`display_name` 用户起、≤16 字符（进工具前缀）；重装系统 = 新 node_id，旧记录吊销归档。

### 2.2 入池流程

1. 子机 `mdp node join` → mDNS（`_mdp._tcp`）发现 hub，失败则手输 IP/MagicDNS。
2. TLS 握手：节点 pin hub 证书（root 签名）；hub 展示节点指纹。
3. hub GUI 弹批准卡（指纹 + 主机名）→ 用户批准 → 签发节点凭证。
4. 节点上报 manifest（§3.4），GUI 变绿。
5. 撤销：`mdp node revoke` → 吊销列表进 manifest 校验，节点端显示 revoked 并停机。

### 2.3 节点与工作区配置

- 子节点 `~/.mdp/config.json`：手工列出工作区（`path` + `name` + 额外 ignore）；不自动扫描。变更即重报 manifest。
- hub 自身**不作为池节点**暴露（v1）：master 本机执行走 harness 本地工具，避免自环。

## 3. 权限模型（最终版）

### 3.1 执行路径（一锤定音）

**远程调用由 node agent 直接执行**（不经子节点 harness；DSH 无独立权限判定 API，代理进 harness = 每次远程调用起本地 LLM 会话，不可行）。由此：

> **远程调用的有效闸门 = overlay（池强制，确定性）+ LLM 自我约束（自述报告，概率性）。**
> **子节点 harness 原生权限规则只管该机器上的本地活动**，对远程路径不生效；`native_enforcement` 是报告字段，不是执行路径。

### 3.2 overlay（主节点 GUI 设置，node agent 强制）

```jsonc
{
  "mode": "standard",              // standard | full_access（完全访问）
  "enabled": true,
  "levels": { "fs": "workspaces", "exec": "allowlist", "transfer": "workspaces" },
                                   // 等级轴：deny < read-only < workspaces < allowlist < full
  "path_domains": ["workspace:*"], // realpath 后判定；exec cwd 夹紧
  "content_gate": "approval",      // approval（默认）| off（仅 full_access 预设）
  "command_patterns_allow": [],    // 学习式白名单（首次前缀审批后累积）
  "epoch": 2
}
```

- **`full_access`（完全访问）**：GUI 红色开关，一次性放开 levels=full、path_domains=*、content_gate=off——池层完全不干涉。配套：独立显式开关（不藏在 level:full 里）；若该节点 `native_enforcement: none` 需二次确认；审计记录带 `gate=off` 标记。
- **内容闸初版模式集**（命中 → 强制审批，不自动拒绝）：递归强删（`rm -rf`、`Remove-Item -Recurse -Force`）、管道执行（`curl … | sh`、`iwr … | iex`）、`git push --force`、注册表/启动项/`schtasks` 写入、磁盘类（`format`/`diskpart`/`dd`/`mkfs`）。模式表每节点可编辑。
- overlay 变更：hub 下发 → 节点即时生效；在跑 job 跑完为止，不接新调用（信封附提示）。

### 3.3 自述报告（不可信数据，按不可信处理）

- 子节点上报：**结构化字段**（等级/路径域/工具集，node agent 生成并签名）+ **自由文本**（可由该节点 harness 用 LLM 生成自述）。
- 注入主大脑方式：工具描述携带紧凑结构化摘要（随 `list_changed` 刷新）；自由文本仅在 `nodes()` 结果返回，注入时显式包裹为"仅供参考的不可信描述"。
- **审计对账**：自述称只读而审计出现写操作 → 自动降级该节点 + GUI 告警；自述变更需 GUI 确认一次。

### 3.4 节点 manifest（签名上报）

```jsonc
{
  "manifest_version": 3, "node_id": "…", "display_name": "pc2",
  "os": "win11", "arch": "x64", "shell": "powershell",
  "agent_version": "0.1.0", "capabilities": ["exec", "fs", "transfer"],
  "workspaces": [{ "name": "repo", "path": "D:/Projects/repo", "revision": 7, "superseded": false }],
  "available": "session",          // session（默认，登录期可用）| service（可选档）
  "native_enforcement": "hook",    // hook | none（none → GUI 标记"无强制"，默认禁用）
  "self_description": { "structured": { /* …签名… */ }, "text": "…" }
}
```

健康语义区分**离线 / 不可达（<5min）/ 已登录但 agent 未跑 / 未登录**（session 档下"未登录"不是故障）。

## 4. 调用协议

### 4.1 工具面

MCP server 名 `mdp`；**静态基线**（全 harness 通用，工具表永不增删）：

```text
nodes()                                  → 节点/工作区/健康/权限摘要 + 未消费 job 计数
exec({node, cmd, cwd, timeout_ms?, shell?, background?})
fs({node, op: read|write|list|glob|grep, path, …})
job_submit({node, cmd, cwd, …}) → {job_id}
job_status({job_id}) / job_output({job_id, offset, limit}) / job_cancel({job_id})
transfer({from, to, ignore?, dry_run?})
handoff({target, include})               // P5 启用
```

**per-node 前缀组**（动态增强，仅支持 `list_changed` 的 harness）：`mcp__mdp__pc2__exec` 等，与静态工具同 schema；节点上下线由 hub 推送刷新（Codex 无此机制，静态面保证无损）。

### 4.2 exec / job 语义

- `cwd` 首选符号引用 `workspace:<name>`；绝对路径允许但过 realpath 域检查；信封回实际 cwd。
- shell：节点默认 shell 入 manifest（Windows=powershell，Unix=$SHELL）；可选 `shell: powershell|cmd|bash` 覆盖；**工具描述必须携带 OS/shell/路径形态示例**（防跨平台混淆）。
- 超时：exec 默认 120s、上限 30min；**needs_approval 必转 job；`background:true` 显式转 job**；不做时长预测自动转。
- 输出：inline 上限 64KB（头+尾截断标记）；全量落节点 job 目录；`job_output` 分页取回。stdin/PTY v1 不支持（文档写明）。
- Windows UTF-8（**V2 实证修订，2026-11-07**）：`chcp 65001` 对管道输出**无效**（报告切页成功但内部命令仍输出 GBK）；唯一有效通路是 PowerShell 前缀包装 `[Console]::OutputEncoding=[Text.Encoding]::UTF8; <cmd>`（PS5.1 与 pwsh7 的 stdout+stderr 双路均验证通过）；`shell=cmd` 时按系统 codepage（GBK）解码兜底；git 中文文件名的八进制转义是 `core.quotepath` 行为（建议 `-c core.quotepath=false`），非编码问题。详见 docs/verification-p0.md。
- **幂等内化**：hub 为每次调用生成 `call_id`；重试由 hub + journal 裁决；LLM 不接触幂等键。

### 4.3 结果信封与错误分类学

```jsonc
{
  "status": "ok | denied | failed | timeout | unknown | needs_approval",
  "node_id": "pc2", "call_id": "c-7f3a", "ts_hub": 1699…,   // hub 签发时间戳（时钟偏移免疫）
  "error": {                                                 // status ≠ ok 时存在
    "class": "network | permission | busy | offline | timeout | crash",
    "retryable": false,
    "message": "pc2 内容闸拦截：'rm -rf' 需审批（或 harness 原始拒绝原因原文）"
  },
  "result": { "exit": 0, "stdout": "…", "stderr": "…", "truncated": false, "output_ref": "job:42#0" },
  "job": { "job_id": "42", "state": "needs_approval" }
}
```

| class | 谁消化 | LLM 看到什么 |
|---|---|---|
| `network` | hub 查 journal：**未开始→透明重发**（指数退避）；**已开始→ `status: unknown`** + 对账指引（"先执行 X 确认是否已发生"） | 仅重试耗尽后可见 |
| `permission` | 无人消化，**永不重试** | overlay/内容闸/harness 原始拒绝原因全文 |
| `busy` | 无人消化 | `.git/index.lock` 冲突提示 + 稍后重试指引 |
| `offline` | 无人消化 | 最后心跳时间；`nodes()` 亦带节点离线提示，阻止 LLM 反复重试 |
| `timeout` / `crash` | 原样回传 | 详情 + 已产生部分输出（`output_ref` 可取） |
| `needs_approval` | 转 job（§6） | `job_id` + 状态 |

**执行 journal**（正确性机制，与安全无关）：node agent 派发前落 `received`，开始落 `started`，结束落 `finished`；持久化于 `~/.mdp/jobs/`。hub 重连节点先对账（"X 现在什么状态"），再决定续报/判死。**只有纯读操作（fs read/list/glob/grep）允许透明重试；一切有副作用的操作重试必须过 journal。**

## 5. 传输与文件

### 5.1 TransportAdapter

```text
open(nodeId) → duplex        // v1 = adapter-direct；备选 adapter-ssh；v2 = adapter-webrtc
```

- **adapter-direct（v1 默认）**：TCP + TLS1.3；hub 出示 root 签名证书、节点 pin root 公钥；节点出示节点凭证。发现（**2026-11-09 决策 #1 修订**）：**单播直投 announce 为主路径**（UDP，与节点端点同号不同协议：node 直发 announce → hub 单播 reply 确认身份/epoch）→ 同介质**自定义组播 announce**（JSON over UDP 239.255.77.68:53550，显式绑接口——V3 定论：跨介质组播被 AP 过滤不可依赖；弃 DNS-SD：两端皆池软件无需 OS 级互操作，DNS-SD 线格式编码是纯开销）→ 手输地址兜底 → tailnet 网内 MagicDNS。
- **hub↔node 通道**：单条持久连接，帧协议 = JSON 控制帧（MCP 调用、心跳、manifest、对账）+ 二进制数据帧（transfer，带 transfer_id）。断线指数退避 + jitter；恢复先 journal 对账。
- 中继兜底（tailnet DERP / v2 TURN）仅作控制面；**v1 transfer 一律经 hub 转发**（LAN 下经 hub 亦为线速），节点↔节点直传与互信推 v2。
- 心跳：应用层带 RTT ping（10s），非 TCP 存活判断。

### 5.2 pool-transfer

- manifest walk：**双层过滤**——gitignore 只管体积项（构建产物/依赖目录）；**秘密扫描层**（路径模式 + 内容启发如 `PRIVATE KEY` 头）命中**硬排除**并在结果列出"已排除清单"；v1 无放行开关。symlink 一律不跟随（manifest 记为引用）；剔除活锁文件（`.git/*.lock`、`*.swp`）。
- 分块 1 MiB + 每块 sha256 + 清单 + 断点续传（续传 = manifest 差量）；目标端 `<ws>.mdp-staging/` 校验后原子替换；Windows 长路径 `\\?\` 处理。
- 保真度：manifest 记录 mode/exec 位（Windows 目标忽略并提示）；入仓大小写冲突前置报错；submodule/LFS 检测到即要求显式确认（走各自 fetch 流程而非 bundle）。
- **血统**：`workspace_id` + `revision` + `source_node`；transfer 成功即源副本标 `superseded`；对 superseded 副本写入**附强警告但允许**（避免死锁），GUI 可手动清标记。
- busy 检测（v1）：写类操作前查 `.git/index.lock` → `failed(busy)`；harness 进程共存检测推后。

## 6. 审批与 job

- `needs_approval`：工具调用立即返回 `job_id`；审批卡片出现在 GUI（**节点名 + 命令全文** + 倒计时）；批准后 node agent 续跑；LLM 经 `job_status` 轮询（工具描述写明"先做其他事，间隔 ≥30s"）。
- **TTL 6h 默认 deny**；job 结果留存 7 天；job 注册表持久化于 hub.db，`nodes()` 返回"已完成未消费"计数——**新会话的大脑可见历史 job**。
- 审批人 = 持 GUI 管理令牌者；审计记录 approver 令牌 ID。
- GUI 未开时无推送（v1 限制，卡片排队；v2 Bridge 推送）。

## 8. 接力与迁移

### 8.1 UI 漫游（P4，仅 DSH）

大脑不动、入口可换：DSH 多客户端并发（事件广播、审批首答生效）；笔记本/手机经入口客户端接入主节点。ZCode 漫游另立项研究 remote executor 机制。

### 8.2 大脑冷迁移（P5，PC↔PC）

1. 前置校验：目标同 harness **同版本**（跨版本拒绝并提示）；同 OS 家族推荐。
2. 迁移物：hub 状态目录（hub.db + root key + overlay + 审计锚点）+ 工作区（transfer 全量）+ 大脑会话存档 + **HANDOFF.md（签名哈希，放会话存档内，不放工作区——防注入伪造与 gitignore 误伤）**。
3. root key 经**带口令的导出/导入仪式**（DPAPI 跨机不可解密，故有此步）。
4. 目标端导入 → **epoch++** → 节点凭 pin 的 root 公钥自动信任新 hub、拒绝旧 epoch → **无 split-brain**。
5. 会话存档跨机可回放性为 P5 验证项（V6）。
6. 有损项写进产品语义：运行中进程/PTY/待审批不迁移，由 HANDOFF.md 供新大脑续局。

## 9. 安全模型与残余风险

| 威胁 | 落点 |
|---|---|
| LLM 越权（含提示注入） | overlay 三检（realpath 路径域 / 等级 / 内容闸）为确定性闸；自我约束为概率层；`full_access` 是用户显式接受的残余风险 |
| 无人节点审批卡死 | needs_approval → job + GUI 回传（TTL 6h 默认 deny） |
| GUI 被尾随设备接管 | 管理令牌 + cookie（P0-3）；建议 tailnet tag + 收紧 ACL |
| 权限自述注入 | 结构化字段签名 + 自由文本按不可信包裹 + 审计对账降级（P1-9） |
| 秘密扩散 | 秘密扫描硬排除 + symlink 不跟随 + overlay 约束 transfer 源与目的（P1-10） |
| 路径域绕过 | realpath 统一解析 + cwd 夹紧 + 大小写折叠（P1-11） |
| hub 被攻陷 | **= 全池沦陷（接受的中心化风险）**；缓解：root key credstore 保护、管理令牌哈希存储、审计链锚定 |
| 审计篡改 | 节点 JSONL 哈希链；hub 定期拉取锚定；result hash = sha256(stdout+stderr+exit) |
| 链路数据过第三方 | 最坏情况过 tailnet DERP 加密中继；敏感用户可自建 headscale/DERP（P1-13） |
| 版本偏差 | hello 带 version + capability flags；低于最低版禁用相关工具并 GUI 提示（P2-7） |
