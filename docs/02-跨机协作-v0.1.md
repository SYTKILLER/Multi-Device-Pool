# 02-跨机协作 v0.1：无人值守 A↔B agent 协作协议 + A 机接线任务书

> 日期：2026-11-18。作者：B 机 agent（ZCode 会话，pc2 侧）。
> 背景：两机开发协作此前靠用户人工中转。本次 B 侧先调查了 GitHub 现存"跨设备多 Agent 协作工具"（结论见 §0），拍板**用自家池自举**——用池协调池的开发 = 工具链路开发验证本身（狗粮）。用户目标：无人值守，两机 agent 自行完成开发任务（当前 = P2 待办）。

## 0. GitHub 工具调查结论（2026-11-18，B 侧）

现存生态三类，**无一个主流项目做"跨设备 agent↔agent 开发协作"**：

| 类别 | 代表 | 星级 | 缺陷（对本目标） |
|---|---|---|---|
| 人机中转面板 | vibe-kanban / omnara / alook | 28.7k / 3.4k / 1.5k | 人在环，agent 均单机；无 agent↔agent 通道 |
| 单机多 agent 编排 | oh-my-claudecode / omnigent / LoopForge | 40.9k / 11.4k / 3.7k | 不跨设备 |
| 跨设备 niche | Agent-MCP(停更 2026-03) / condrix(停更) / mailbox-mcp(0★) | ≤1.3k | 低采用+停更，引入成本 > 自举两根线 |

结论：空白验证了本项目选题；自举路线 = A 机 node 常驻 + token 交接（§2/§3），不引入外部依赖。

## 2. token 交接（A 机 agent 执行——双向通道的最后一把钥匙）

1. `git pull` 本仓库（拿到本文档）。
2. 读 A 机本机 `~/.mdp/hub-info.json` 的 `token` 字段。
3. 经插件面写 pc2 工作区：`fs {node:"pc2", op:"write", path:"workspace:repo/.mdp-hub-token.json", content:"{\"hub\":\"http://192.168.1.42:7800\",\"token\":\"<token>\",\"written_at\":\"<ISO时间>\"}"}`。
4. **安全纪律**：token 不入 git（ws-repo 已 gitignore，天然隔离）；P0 通道明文 TCP，仅限可信局域网（01 §2.1 / CROSS-MACHINE.md 安全注记）。
